# 简记 · 全面审计与开源借鉴（面向 1.0.5+）

审计时间：2026-09-14。方法：20 个并行 Agent —— 12 路代码/UI/链路审计 + 8 路开源对标调研，
关键 P0 结论均经人工回读源码复核（有一条误报已剔除，见文末）。

## 总体评价

工程质量高于典型个人项目：金额全链路 Long 分（无浮点误差，且有回归测试）、权限最小化、
备份命名防多设备冲突、恢复前本机留底、6 个 JVM 单测。定位是"自己用五年的账本"，
**最大的系统性风险集中在数据链路，交互与可视化次之，功能面（转账/预算/初始余额）是实用性最大缺口。**

做得好、不要动的：Money 实现、Manifest 权限面、备份命名、依赖刻意锁旧（离线缓存）、无 CI/androidTest（自用不值得补）。

## 一、P0 —— 数据安全第一梯队（建议全部进 1.0.5）

1. **静默清库 × 自动上传的组合漏洞（全项目最高危）**
   `Ledger.kt:190` `fallbackToDestructiveMigration()` + 空 MIGRATIONS：下次加字段忘写迁移 → 整库清空；
   而记一笔后 3 分钟防抖就会触发上传（`LedgerViewModel.kt:87`），`BackupWorker.kt:98` 无条件覆盖云端"最新版"
   → **一次坏升级把空库推上云，唯一的好备份也被顶掉**。
   修复：删除 destructive 兜底（缺迁移直接崩，比丢数据好）；云端覆盖前校验交易数骤降则拒传并通知。

2. **恢复不是原子的、格式不向前兼容**
   `BackupCodec.kt:92-94` 三表写入无 `@Transaction`，JSON 中途损坏留半恢复态；
   `BackupCodec.kt:24` 的 Json 缺 `ignoreUnknownKeys`（迁移解析有、备份恢复反而没有）；
   `BackupDto` 无 schemaVersion 字段。修复：事务包全量替换、加 version、宽松解析。

3. **返回键与进程重建会吞掉一切现场**（grep 全项目：BackHandler 0 处、rememberSaveable 0 处）
   记一笔中途按返回 = 退出 App + 草稿全丢（`AddScreen.kt:75-90`、MainActivity 导航态全用 remember）。
   修复：overlay 级 BackHandler 回上一级；表单态/导航态改 rememberSaveable。

4. **物理删除不可逆**：`Ledger.kt:126` deleteTx 硬删，无撤销无回收站。
   修复：删除后 5s Snackbar 撤销（成本最低），或软删 deletedAt。

5. **备份失败完全静默**：`BackupWorker.kt:33-39` 只写 DataStore lastResult。密码失效 → 数月没备份，丢机即全丢。
   修复：失败发通知；备份页显示"距上次成功 N 天"红条。

6. **孤儿账单与完整性缺失**：无外键、无 CHECK，null categoryId 写成 `""`（`Ledger.kt:236`），
   `LedgerViewModel.kt:48` accountId() 可能读到 stateIn 重置的空表 → 落库 accountId=""，账户统计永久对不上。
   修复：DAO 取不到账户就拒绝保存并提示；备份导入时兜底到"未分类"。

## 二、P1 —— 明显缺陷（1.0.5 挑顺手的做，其余 1.1）

- **导航**：`AppShell.kt` 无 NavHost，enum Overlay 单槽无返回栈，搜索→详情→返回一路跌回 Tab；
  detailTx 持整个对象快照，外部改动不回溯。改 NavHost + 路由传 id。
- **并发/唯一性**：orderNum 用 StateFlow 缓存算 max+1 会撞号（DAO 内 SELECT MAX + 事务）；
  账户/分类名无唯一约束；先 COUNT 再 DELETE 两步非原子。
- **查询效率**：`Ledger.kt:100` observeAll 全表 + @Relation，首页/统计/搜索/导出全内存过滤；
  transactions 表零索引（dateTime/accountId/categoryId 该加）；列表无 Paging。
  个人数据量下短期无感，但备份导出期间记账会产生跨时间点快照（应单事务读）。
- **凭证安全**：`NutstoreConfig.kt:41` WebDAV 应用密码明文 DataStore → EncryptedSharedPreferences。
- **记账输入流（实用性评分 4/10）**：无九宫格数字键盘、保存即清空无连续记账、
  dateTime 恒为 now（改日期不能改时刻，补记无法插到当天正确位置）、校验静默吞字符、
  无"记住上次账户/常用分类前置"、表单分类多了把保存按钮挤出屏幕。
- **账单/搜索**：筛选只有时间维（无分类/账户/金额区间）、金额按子串匹配（"5" 命中 "15.00"）、
  无批量多选、无月份快速跳转、组头不用 stickyHeader。
- **统计**：图表零点选交互、无 Y 轴刻度、无日/周/年粒度与同环比、Canvas 无 semantics（TalkBack 完全不可用）、
  占比整除截断不足 100%、小扇区 gap 致消失。
- **视觉/无障碍**：黄底白字对比 2.01:1（`CategoryManageScreen.kt:216`）、浅色支出红/收入绿不达 AA 4.5:1、
  底栏 46dp/FAB 附近 22dp 触控 <48dp、fontScale≥1.3 溢出、蓝顶区 25 处 Color.White 硬编码。
- **设置面**：无主题三态（只有跟随系统）、无归档账户、管理页有 orderNum 却不能拖拽排序、
  删除被"有账单"拦死时不提供"改派后删除"。
- **导出**：CSV 无账户列、主线程写 IO（ExportScreen.kt:92）、0 笔也写文件、无分享、未防公式注入。
- **测试**：最高价值的一项是**备份往返单测**（export→import→逐条比对），纯 JVM 可做。
  Room 迁移测试等首次真改 schema 前再补。

## 三、功能缺口 —— 开源对标的结论（1.1 主线）

按借鉴度排序（来源：MyExpenses、MMEX、Firefly III、Actual Budget、一羽/钱迹/熊猫记账等）：

1. **转账建模 [★5]**：现在 isExpense 两态，账户互转记成一收一支双计，污染统计和余额。
   业界最小方案：单条记录加可空 `toAccountId`（MMEX/Actual 都是这样裁剪复式），
   统计收支时排除转账流，账户余额按腿派生。**这是余额正确性的根，宜早不宜迟。**
2. **初始余额 + 余额修正 [★5]**：`AccountEntity` 加 initialCents；
   Firefly/Actual 的共识是**禁止静默改余额**——修正 = 自动生成一条带说明的"调整"流水留痕。
   五年账本迟早要和真实银行对账，没有这个口子账就废了。
3. **预算 [★4]**：目前 grep 不到任何预算代码。借鉴 Actual envelope 裁剪版：
   总/分类月度预算 + 首页环形进度 + 超额通知；MyExpenses 的 rollOver（未花完自动结转）值得要。
   熊猫记账的"今天还能花 = (预算-已花)÷剩余天数"放在首页，是最实用的一屏。
4. **定期交易 [★4]**：MMEX/MyExpenses 用 RRULE+WorkManager 到期通知"一键记账/跳过"，
   订阅/房租/花呗还款都靠它。分期 = RRULE 限次数。
5. **标签 [★★★]**：Actual 直接解析备注里的 #xxx，零 UI 成本，分类管统计、标签管"旅行/报销"维度。可 v2 再说。
6. **快捷入口 [★5 性价比]**：Shortcuts 静态声明"记支出/记收入"深链（S，最先做）→
   Glance 桌面小部件（本月支出+记一笔，M）→ QS Tile / 分享截图入口（M）。
7. **微信/支付宝账单导入 [★4]**：double-entry-generator 已趟平坑——微信 UTF-8 前 17 行元数据、
   支付宝 GBK 编码第 5 行表头、剔除"收/支=/"与 0 元行、退款净额。做专用 preset +
   hash(日期+金额+备注) 幂等去重。
8. **分类图标 [★3]**：现在只有改名换色、列表用名称首字，Actual/一木用 emoji 当图标是零成本正解。

## 四、备份链路强化（开源调研落地版）

现状三表齐全、命名防冲突、恢复前留底，方向对。补强按序：

1. 快照正确姿势：直读运行中的 Room 库有 WAL 半写风险 → **VACUUM INTO 临时库再导出**。
2. 原子上传：先传临时名 → WebDAV MOVE 转正，永不覆盖写。
3. 覆盖云端"最新版"前：行数骤降校验 + 备份世代号（防清库后旧数据倒灌回写）。
4. 保留策略 GFS（日 7 周 4 月 12），归档目录逐目录降级列出（现在一个 PROPFIND 失败全列不出）。
5. 恢复前校验：文件头写 schemaVersion/行数/SHA-256，验完再入库；恢复留底也上一份到云。
6. 可选加密（Keystore 包裹密钥，坚果云只存密文）——账目敏感度高再做，非急。

## 五、明确不做的事

- 迁移到 Vico 图表库（自绘已成熟，迁移成本>收益；饼图 Vico 还标 experimental）。
- Material3 Expressive（还在 1.5.0-alpha，等 stable）。
- 双向同步（单设备自用，WebDAV 备份+LWW 恢复合并足够；不要上 Merkle 树）。
- 升级依赖版本（刻意对齐离线缓存，无高危 CVE）。
- CI / androidTest。
- 可以采用的现成件：M3 1.4.0 `SwipeToDismissBox`（已 stable，左滑删一行）、
  kizitonwose Calendar 2.10（若要日历热力图，热力着色仍自绘）；数字键盘无成熟库，自研。
